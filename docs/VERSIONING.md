# Application version policy

The root `package.json` → `version` is the **single editable source of truth** for the application version. Use a stable `major.minor.patch` release version. Do not maintain a second version constant in TypeScript, translations, CI or packaging code.

| Consumer | Source / synchronization |
| --- | --- |
| npm lockfile root and root package entry | Generated together by `npm version`; checked against root package.json |
| Tauri bundle and window title | `tauri.conf.json` reads `"../package.json"`; the app name comes from `productName` |
| About dialog, all languages | The build-identity file generated at build time (see below) |
| Installer/archive filenames (MSI, NSIS, deb, AppImage) | Generated by the Tauri bundler from root package.json |
| English/Chinese CHANGELOG | Historical records, not build inputs; the first release heading must match root version |
| CI | Executes the same version gate; no application version literal in YAML |

Third-party library versions are not application versions. The Rust shell crate intentionally keeps `version = "0.0.0"` because Tauri reads the application version from the root package.json. Windows executables are unsigned; the Rust MSRV tracks the current stable toolchain (see docs/migration/IMPLEMENTATION.md).

For a new release:

```sh
npm version <major.minor.patch> --no-git-tag-version --ignore-scripts
# Add matching release entries to CHANGELOG.md and CHANGELOG.zh-CN.md.
npm run check:version
npm run build
npm run package
```

The build and package commands run the consistency gate automatically. `npm version` here does not create a commit or tag. Changelog entries are written manually as history, and verified rather than used to determine the application version. README download examples use `<version>` to avoid stale current-version copies.

## About build provenance

`scripts/tauri-build-info.mjs` generates the build-identity JSON (package version, `git rev-parse HEAD`, working-tree status, and the fixed build-time UTC clock) before and after the frontend build, and copies it into the frontend output where the app reads it at startup. About shows the package version, full commit, modification indicator and the fixed ISO 8601 UTC build timestamp. The timestamp is not the commit date or launch time. CI uses the actual checked-out commit (including GitHub PR merge commits). Set `SOURCE_DATE_EPOCH` to Unix seconds when a reproducible timestamp is needed. Git is required at build time only; packaged applications read the bundled JSON with no Git or network access. The Rust build script (`src-tauri/build.rs`) refuses to compile when the identity is stale, so run `node scripts/tauri-build-info.mjs` before invoking Cargo directly.
