# Application version policy

The root `package.json` → `version` is the **single editable source of truth** for the application version. Use a stable `major.minor.patch` release version. Do not maintain a second version constant in TypeScript, translations, CI or packaging code.

| Consumer | Source / synchronization |
| --- | --- |
| npm lockfile root and root package entry | Generated together by `npm version`. Checked against root package.json |
| Tauri bundle and window title | `tauri.conf.json` reads `"../package.json"`. The app name comes from `productName` |
| About dialog, all languages | The build-identity file generated at build time (see below) |
| Installer/archive filenames (MSI, NSIS, deb, AppImage) | Generated by the Tauri bundler from root package.json |
| English/Chinese CHANGELOG | Historical records, not build inputs. The first release heading must match root version |
| CI | Executes the same version gate. No application version literal in YAML |

Third-party library versions are not application versions. The Rust shell crate intentionally keeps `version = "0.0.0"` because Tauri reads the application version from the root package.json. Windows executables are unsigned. [Cargo.toml](../src-tauri/Cargo.toml) declares the minimum Rust version.

For a new release:

```sh
npm version <major.minor.patch> --no-git-tag-version --ignore-scripts
# Add matching release entries to CHANGELOG.md and CHANGELOG.zh-CN.md.
npm run check:version
npm run build
npm run package
```

The build and package commands run the consistency gate automatically. `npm version` here does not create a commit or tag. Write changelog entries manually as release history. The version check compares release headings with the application version. README download examples use `<version>` to avoid stale current-version copies.

Keep English and Chinese changelog entries brief and limited to changes users
notice in everyday use. Omit implementation details, developer work and
minor optimizations. Omit a change if its value to users is unclear. Use the
release history to date entries accurately. See the
[documentation rules](../AGENTS.md#documentation-and-versioning) for language
and content requirements.

## About build provenance

`scripts/tauri-build-info.mjs` generates build identity before and after the frontend build.
The script copies the JSON into the frontend output. The app reads this file at startup.

About shows these values:

- Application version.
- Full commit from `git rev-parse HEAD`.
- Working-tree modification indicator.
- Fixed build timestamp in ISO 8601 UTC format.

The timestamp records build time, not commit time or launch time.
CI records the checked-out commit, including GitHub pull-request merge commits.
Set `SOURCE_DATE_EPOCH` to Unix seconds when a reproducible timestamp is needed.

Git is required only during builds. Packaged applications read the bundled JSON without Git or network access.
The Rust build script (`src-tauri/build.rs`) rejects stale build identity.
Before invoking Cargo directly, run `node scripts/tauri-build-info.mjs`.
