# Application version policy

The root `package.json` → `version` is the **single editable source of truth** for the application version. Use a stable `major.minor.patch` release version. Do not maintain a second version constant in TypeScript, translations, CI or packaging code.

| Consumer | Source / synchronization |
| --- | --- |
| npm lockfile root and root package entry | Generated together by `npm version`; checked against root package.json |
| About dialog, all languages | Electron `app.getVersion()` reads the application's package.json; app name comes from `app.getName()` |
| Packaged `resources/app/package.json` | Generated by package-app.js from root package.json |
| Archive filenames and app-version.txt | Generated from root package.json |
| Windows FileVersion/ProductVersion | Executable version strings use root version; numeric resource uses major.minor.patch.0 |
| macOS CFBundleVersion/CFBundleShortVersionString | Generated from root package.json |
| English/Chinese CHANGELOG | Historical records, not build inputs; the first release heading must match root version |
| CI | Executes the same version gate; no application version literal in YAML |

Electron's dependency/runtime version is intentionally separate. Portable packages label its original version file `electron-version.txt`, while `app-version.txt` identifies this application. Third-party library versions are not application versions. Windows executables are unsigned after their application metadata is updated; macOS bundles retain local ad-hoc signing only.

For a new release:

```sh
npm version <major.minor.patch> --no-git-tag-version --ignore-scripts
# Add matching release entries to CHANGELOG.md and CHANGELOG.zh-CN.md.
npm run check:version
npm run build
npm run package
```

The build and package commands run the consistency gate automatically. `npm version` here does not create a commit or tag. Changelog entries are written manually as history, and verified rather than used to determine the application version. README download examples use `<version>` to avoid stale current-version copies. Existing archives from earlier builds retain their historical version and are not relabeled.

## About build provenance

`build:main` generates `dist/src/main/build-info.json` from package.json, `git rev-parse HEAD`, working-tree status, and the build-time UTC clock. About shows the package version, full commit, modification indicator and the fixed ISO 8601 UTC build timestamp. The timestamp is not the commit date or launch time. CI uses the actual checked-out commit (including GitHub PR merge commits). Set `SOURCE_DATE_EPOCH` to Unix seconds when a reproducible timestamp is needed. Git is required at build time only; packaged applications read the local JSON with no Git or network access. The generated file is included in the app payload and packaging rejects version mismatches.
